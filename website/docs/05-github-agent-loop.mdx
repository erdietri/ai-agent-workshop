# Agent Loop

Alright, now we need to add a **loop** to our model. This allows it to continue asking for more information until it has what it needs to complete the task. First we need to remove the test message we added earlier, and then we will add a loop that will continue until the model has what it needs to complete the task.

The loop is like a context for the model but only for its internal information before sending the data back to us. Without this loop, the model would make a _tool call_, but not be able to get the data back without it being added to the _messages array_. This is because the model does not have access to the tool, it only knows that it can call it. The code we are adding will allow the model to get the data back from the tool and return it to us.

## Create the Loop

```python title="agent.py" showLineNumbers
import os
import ollama
import requests

GITHUB_API_KEY = os.getenv("GITHUB_TOKEN")

SYSTEM_PROMPT = """You are a project manager and you are helping a user with their GitHub repository. You have access to the GitHub API and can perform actions such as creating issues, closing issues, updating issues, organizing and managing projects. You can only answer from the tools you are given. You will be given a task by the user and you will use the GitHub API to complete that task. You will not make any changes to the repository or project without explicit instructions from the user. You will not make any assumptions about the user's intentions or goals. You will always ask for clarification if you are unsure about what the user wants you to do. You will always provide clear and concise feedback to the user on the status of their task and any errors that may occur."""

messages = [
    {"role": "system", "content": SYSTEM_PROMPT},
]

GITHUB_HEADERS = {
    "Authorization": f"Bearer {GITHUB_API_KEY}",
    "Accept": "application/vnd.github+json",
    "X-GitHub-Api-Version": "2022-11-28",
}

def list_repos():
    """
    List all of the repositories the user has access to, most recently updated first.

    Returns:
        list: The repositories, each with its full name, description, language and whether it is private.
    """
    repos = []
    for page in range(1, 11):  # GitHub sends 100 per page, so this stops at 1,000
        response = requests.get(
            "https://api.github.com/user/repos",
            headers=GITHUB_HEADERS,
            params={"sort": "updated", "per_page": 100, "page": page},
            timeout=10,
        )

        # Return the error as text so the model can tell the user what went wrong.
        if response.status_code != 200:
            message = response.json().get("message", response.reason)
            return f"GitHub error {response.status_code}: {message}"

        repos += response.json()
        if len(response.json()) < 100:
            break

    # Keep only the fields the model needs to tell the repositories apart.
    return [
        {
            "full_name": repo["full_name"],
            "description": repo["description"],
            "language": repo["language"],
            "private": repo["private"],
        }
        for repo in repos
    ]

# diff-remove-start
messages.append({"role": "user", "content": "What repositories do I have?"})

response = ollama.chat(model="qwen3.5:4b", messages=messages, tools=[list_repos], think=False)
messages.append(response.message)

# If the model asked for a tool, run it and add the result to the conversation.
if response.message.tool_calls:
    call = response.message.tool_calls[0]
    result = list_repos(**call.function.arguments)
    messages.append({"role": "tool", "tool_name": call.function.name, "content": str(result)})

    # Ask again so the model can read the result and answer.
    response = ollama.chat(model="qwen3.5:4b", messages=messages, tools=[list_repos], think=False)

print(response.message.content)
# diff-remove-end
# diff-add-start
##########################################
### Agent Loop
##########################################
TOOLS = {"list_repos": list_repos}

def run_tool(call):
    """Run one tool call from the model and return the result as text."""
    tool = TOOLS.get(call.function.name)
    if tool is None:
        return f"Unknown tool '{call.function.name}'."

    # Return any error as text so the model can see what went wrong and try again.
    try:
        return str(tool(**call.function.arguments))
    except Exception as error:
        return f"Error calling {call.function.name}: {error}"


def run_agent(user_input):
    messages.append({"role": "user", "content": user_input})

    for _ in range(10):  # stop after 10 rounds so a confused model cannot loop forever
        response = ollama.chat(model="qwen3.5:4b", messages=messages, tools=list(TOOLS.values()), think=False)
        messages.append(response.message)

        # No tool calls means the model has its final answer.
        if not response.message.tool_calls:
            return response.message.content

        # Run every tool the model asked for and add the results to the conversation.
        for call in response.message.tool_calls:
            result = run_tool(call)
            messages.append({"role": "tool", "tool_name": call.function.name, "content": result})

    return "I stopped because this took too many steps."


while True:
    user_input = input("You: ")
    if user_input.strip() == "/bye":
        break
    print("Agent:", run_agent(user_input))
# diff-add-end
```

In the above code we added a **tools dictionary** that maps tool names to functions. We also added a **run_tool** function that takes a tool call from the model, runs the corresponding function, and returns the result as text. The **run_agent** function is the _main loop_ that takes user input, sends it to the model, runs any tools the model asks for, and returns the final answer. Then the _while loop_ at the end allows the user to interact with the agent until they type "/bye".

Now lets add a few more tools so the agent can be more useful to us.

## Add More Tools

### Get Repository Tool

Now we will add a tool that allows the model to get information about a specific repository. It will be able to get the full name, description, whether it is private, the default branch, the number of open issues, and the URL of the repository. This will allow the model to get more information about a specific repository and use that information to complete tasks.

### Get Repository Issues Tool

This next tool is the one we have been waiting for. The other tools before this were so that the model can get information it may need to be able to get this point. Like giving it a generic repository name and it can find it using the previous tools. Though this is _read only_ right now, it can still help us prioritize issues and find the ones we need to work on.
